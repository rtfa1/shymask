# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` holds architectural decision records.

## Before exploring

Read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms consistently in issues, proposals, code, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, naming the ADR
and explaining why the decision may need to be reopened.
